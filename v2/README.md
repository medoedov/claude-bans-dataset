# Расширение датасета: ноябрь 2026

Продолжение исследования первой статьи на Habr. Старый файл `../cases.csv` и прежние расчёты сохранены как версия 1. Здесь — объединённый набор с новыми историями, продолжениями старых аккаунтов и явными исправлениями. Точные размеры и состав — в [results.md](results.md) и [build-summary.json](build-summary.json).

| Файл | Назначение |
|---|---|
| cases.csv | Версия 1 плюс принятые новые аккаунты; для старых аккаунтов с продолжением — последнее подтверждённое состояние |
| events.csv | События из нового исследования; разные этапы KYC, бан, восстановление, апелляция и последующий доступ |
| details.csv | Подробные признаки нового наблюдения в JSON: документ, проверяющий, расход, точность дат и другие известные сведения |
| sources.csv | Публичные ссылки нового исследования, доступные для проверки; приватные исходники не публикуются |
| changes.csv | Добавления, продолжения и исправления атрибуции старых свидетельств |
| schema.md | Значение полей и отличия от версии 1 |
| method.md | Сбор, отбор, дедупликация, проверка и ограничения |
| analyze.py | Воспроизводимый подсчёт состава расширения; требуется только стандартный Python3 |
| summary.json, results.md | Результаты `python analyze.py` из каталога v2 |
| build-summary.json | Контрольная сумма входной версии 1 и число решений/новых строк/событий |

`cohort=addition` — новый различимый аккаунт. `legacy_followup` — продолжение прежнего case_id, которое не увеличивает число аккаунтов. `legacy` — прежняя строка без нового наблюдения. При продолжении неизвестные текущие характеристики не наследуются автоматически из раннего рассказа: прежние значения остаются в версии 1.

`active` означает подтверждённый доступ на дату наблюдения, а не отсутствие будущего бана. Старое `survived` сохранено только у неизменённых строк версии 1. Подтверждённый бан, временное ограничение и запрос KYC считаются разными исходами.

Это добровольные рассказы, а не случайная выборка пользователей. Доли не являются вероятностями бана. Старый и новый сбор различаются: объединённые строки не доказывают изменение политики или влияние тарифа, IP, документов и расхода. Версия 1 не получила автоматическую повторную разметку по новым правилам.

Часть новых историй получена из предоставленных автором экспортов чатов. Для них опубликованы только обезличенные признаки и пересказ; `url` пустой, `evidence_visibility=private`. Сырые сообщения, имена, внутренние ключи авторов, реквизиты и документы не публикуются. Их полная независимая проверка по этому репозиторию невозможна; это ограничение источника, а не подтверждение достоверности истории.

В build-summary.json `baseline_sha256` относится к байтам локального неизменяемого снимка. Windows/Git могут менять окончания строк: для сверки скачанного исходного cases.csv используйте `baseline_sha256_lf` после замены CRLF на LF. Этот хеш совпадает с исходным Git-объектом версии1.
