# Схема версии 2

`cases.csv` сохраняет порядок 24 колонок версии 1, затем добавляет пять полей. Совместимые значения описаны в `../schema.md`; правила ниже уточняют их для новых наблюдений и имеют приоритет. Старые значения не исправлялись массово.

| Поле | Значение |
|---|---|
| case_id | Старый ID сохранён при продолжении; новые ID имеют префикс v2 и фиксируются для этого выпуска |
| cohort | legacy / legacy_followup / addition |
| product | consumer / console_api / team_organization / unknown. Слово organization само по себе не означает тариф Team |
| evidence_class | firsthand / detailed_colleague / forwarded_testimony / legacy_unreviewed |
| evidence_visibility | public / private |
| last_observed_at | Последняя подтверждённая дата наблюдения, без продления по молчанию автора |
| outcome | banned / locked / active / kyc_prompt / unbanned. У неизменённой версии 1 остаётся также survived |
| post_date | Дата сообщения об этом наблюдении. Может отличаться от даты события |
| ban_date | Точный или восстановленный из прямого относительного указания день бана; иначе пусто. Тип точности отдельно в events |
| wave | Не назначается автоматически по дате сообщения; новые волны не сравниваются по этому полю |
| plan | free / pro / max5 / max20 / team / enterprise / api / ultra / custom / unknown; конфликт тарифов не снимается догадкой |
| usage | heavy / normal / light / unknown, только за подтверждённый период перед соответствующим исходом. Подробности —details |
| kyc | passed / requested / none / unknown; общий статус не доказывает решение конкретного провайдера или сохранение доступа |
| user_region | Физическое местонахождение по прямому свидетельству; язык, паспорт и IP его не устанавливают |
| group | Наследуемая группа источников RU/CN/WORLD; не подтверждённое гражданство или местонахождение |
| notes, usage_evidence | Обезличенный пересказ; без имён/реквизитов/дословных длинных цитат |

Неуказанное поле —unknown, а не отрицание. Для дат, возраста и отсутствующего usage_evidence используется пустая строка. Страна карты не означает владение картой. Год регистрации не превращается в точное число месяцев. Стабильная страна выхода не доказывает стабильный IP. Возраст почты не возраст Claude. Тариф не показатель расхода, API-equivalent не себестоимость компании.

## События

`event_id,case_id,date,date_precision,event,note,url,visibility,sequence_refs`. precision: exact, inferred, before_or_on, reported_on, month, unknown. Для month дата YYYY-MM; при unknown может быть пустой. reported_on означает дату сообщения без утверждения, что событие произошло в тот же день. Последовательность не додумывается по сортировке строк.

`sequence_refs` сохраняет порядок внутри размеченного рассказа: например `sequence-0001:1` и `sequence-0001:2`. Если даты одинаковы или неизвестны, этот порядок сохраняет «проверка → бан» и «бан → проверка во время апелляции». Объединённое событие может иметь несколько ссылок, разделённых точкой с запятой. Номера sequence — публичные технические ID; они не кодируют имя или исходный номер сообщения. Разные последовательности не задают автоматически полный порядок всех событий аккаунта.

Основные события:kyc_requested,kyc_attempt_failed,kyc_passed,banned,active,reinstated,appeal_rejected,refund_received. Дополнительные названия описывают конкретное сообщение:plan_changed,subscription_expired и другие. Они не сворачиваются автоматически в бан. События не реконструированы для всех 1693 старых строк: таблица отражает новое исследование.

## Дополнительные признаки

`details.csv`:case_id,observed_at,details_json. JSON содержит только известные или явно отмеченные как unknown поля. В частности:document_country/type; verifier_is_account_user; kyc_provider/result; claude_access_after_kyc; usage_quantity/unit/window/temporal_relation; plan_conflict; date_precision; network/client; account_relation; source_selection. Отсутствующий ключ равнозначен неизвестному признаку.

Документ, гражданство, физическое местонахождение и IP разделены. Принятый документ и доступ Claude — разные события. Неудачная проверка без названной причины не кодируется техническим сбоем. Persona не присваивается по общему слову KYC. Расход без доказанной связи с периодом перед событием остаётся в details, а root usage=unknown.

Связи аккаунтов одного владельца и спорные дубли учитываются в локальном аудите. `related_case_ids` содержит только публичные ID принятых строк, если ссылка на связанный аккаунт явно задана. Внутренние названия карточек и ники не публикуются. Публичные ID строк не являются ID людей. Совпадение отображаемого имени в Telegram недостаточно для объединения.

Несколько источников могут описывать один реальный эпизод. Одинаковые записи событий объединены, но строки events.csv не равны числу независимых банов или попыток KYC. При объединении аккаунтов дополнительные источники, события и наблюдения признаков сохраняются. Недатированная дополнительная ссылка может подтверждать уже включённый датированный аккаунт; она не определяет дату его исхода.
